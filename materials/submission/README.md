## Воспроизведение проверок

Выполните из корня клона проекта с Python 3.11+. Подготовка зависимостей может использовать сеть; сама проверка выполняется офлайн.

```sh
python -m pip install --no-deps -r tests/requirements-schema.lock
PYTHONPATH=src python -m genesis.cli verify --all
PYTHONPATH=src python -m genesis.cli demo
PYTHONPATH=src python -m genesis.generation.datasets check --dataset data
PYTHONPATH=src python -m unittest discover -s tests -p test_trajectories.py -v
```

В PowerShell задайте `$env:PYTHONPATH = 'src'` и запустите команды Python без префикса `PYTHONPATH=src` (либо установите пакет локально: `python -m pip install --no-deps --no-build-isolation -e .` и используйте `genesis verify --all` / `genesis demo`).

Команды сборки и проверки в контейнере на Linux. Собранный образ можно перенести на машину без сети. [Сборка и перенос](../../docs/OFFLINE_RUN.md#сборка-и-перенос)

```sh
docker build --tag genesis-verify:local .
docker run --rm --pull never --network none --cpus 2 --memory 4g --memory-swap 4g \
  --read-only --tmpfs /tmp:rw,nosuid,nodev,noexec,size=64m,mode=1777 \
  --cap-drop ALL --security-opt no-new-privileges --pids-limit 64 \
  genesis-verify:local python -m genesis.cli verify --all
docker build -f Dockerfile.policy --tag genesis-policy:local .
```

- В локальном прогоне `verify --all` на `202c282` прошли 183 теста, 20 из 20 повторов, 20 из 20 пар с перестановкой ID и 80 из 80 запусков политик. Диагностическая серия использовала 20 компактных KZT-профилей с часовым поясом Asia/Almaty и курсом на дату платежа. [Методика](../../benchmarks/README.md) · [Офлайн-проверка в CI](https://github.com/24kBlood/GenesisHackathon/actions/runs/44990377392)
- **CLI-демо (`demo`):** `simple_reconciliation` на `seed=20260304` завершается за 5 шагов (`TP=1 FP=0 FN=0, F1=1,0000, return=0,9920`), `oracle` — за 1 шаг (`F1=1,0000, return=1,0000`).
- **Данные (`datasets check`):** `20` публичных эпизодов (`10 train`, `10 dev`) проходят побайтовую сверку контрольных сумм; `train` содержит `16–239` проводок (`7–115` документов), `dev` — `16–226` проводок (`7–111` документов), включая 4 масштабированных 60-обязательных эпизода (`221–239` проводок, `105–115` документов).
- **Траектория (`test_trajectories.py`):** 10 тестов проходят; реальный `data/train` эпизод `episode-ce7be9493ab47ff2dd4555c4` (`seed=20260110`) завершается на 11-м шаге с терминальной наградой `0,98` (8 TP / 0 FP / 0 FN). SHA-256 файла `2bf23bf9191b1cf1953818a4d3aff650c0a2572fc1fb2162d381587a699273b6`.

Все указанные прогоны измеряют состояние локального синтетического решения. Результаты официальной закрытой оценки жюри определяются отдельно на закрытой выборке.

## Перед подачей

1. Зафиксировать итоговый SHA после слияния ветки в `main` и повторить офлайн-проверку (`offline-verify.yml`), изоляцию (`policy-isolation.yml` с `--require-docker`) и replay на этой версии.
2. Записать видеодемонстрацию до 3:00 (можно с показом `genesis demo` и `genesis verify --all`), подготовить презентацию, собрать все ссылки в одном документе Google Drive и проверить открытие каждого материала с правами жюри.
3. Капитан отправляет ссылку через кабинет Genesis и сохраняет отметку времени и подтверждение. При сбое сохраняет скриншот, время и описание для обращения к организаторам.
