# Открытые данные Genesis FinTech

Версия набора и генератора — `1.1.0`, версия схем — `1.0.0`. Проводки открытия включают кассовый резерв, а эталонные ID распределения и дубля используют единые правила. В `train/` и `dev/` находятся по десять синтетических эпизодов. В каждом эпизоде опубликованы только `manifest.json`, `ledger.csv`, `invoices.jsonl`, `payments.jsonl`, `fx.csv` и `policy.json`. Исходный код генератора обеспечивает воспроизведение. Seed официальной проверки жюри в наборе отсутствуют.

## Состав

| Набор | Эпизоды | Проводки на эпизод | Счета | Платежи | Документы на эпизод | Курсы |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| train | 10 | 16–239 | 4–64 | 3–51 | 7–115 | 2–28 |
| dev | 10 | 16–226 | 4–62 | 3–49 | 7–111 | 2–28 |

В каждом наборе представлены чистые эпизоды (с отвлекающими операциями и без них), все четыре одиночных класса ошибок (включая как пропущенное, так и частичное `payment_allocation`, а также обе стороны границы `period_cutoff` — до `period_start` и на/после `period_end`), оба взаимодействующих сценария и комбинированные случаи с числом ошибок от `0` до `12` на эпизод. Набор охватывает 5 валют (`EUR`, `GBP`, `JPY`, `KZT`, `USD`), 4 часовых пояса IANA (`America/New_York`, `Asia/Almaty`, `Europe/Berlin`, `UTC`), оба правила даты курса (`payment_date` и `invoice_date`) и неточные FX-конверсии с `ROUND_HALF_EVEN`. Четыре масштабированных эпизода (`obligation_count=60`, по два в `train` и `dev`) содержат `221–239` проводок и `105–115` документов, проверяя постраничное чтение с курсорами в ориентирном диапазоне ТЗ (`200–2 000` проводок и `20–200` документов). Остальные эпизоды остаются компактными для быстрой ручной проверки причинных цепочек.

[Индекс train](configs/train_configs.json) и [индекс dev](configs/dev_configs.json) содержат последовательность записей с открытым `seed` и нормализованной `config`. Генератор получает эти значения отдельно, возвращает `episode_id` и записывает его в manifest. Из этой последовательности строится [сводка](checksums.json) с ID, split, размерами, SHA-256 каждого из шести файлов и SHA-256 книги без синтетических идентификаторов и порядка выдачи строк. Сравнение книг учитывает публичные связи счетов, платежей, возвратов и проводок через содержимое связанных записей. Хэши файлов вычисляются по каноническим байтам UTF-8 с LF. Логи, метаданные файловой системы и пути не входят в расчёт.

Обновляйте версию набора при изменении состава индексов, версию генератора при изменении его воспроизводимого вывода и версию схем при изменении контракта. При выпуске новой версии одновременно обновляйте константы проверяющего модуля и индексы, регенерируйте файлы и публикуйте пересчитанную сводку.

Доверенный harness при необходимости может вызовом `generate_episode(seed, config)` получить эталон в своей памяти. Команда публикации выбирает исключительно открытые артефакты. Открытые seed служат воспроизводимости train и dev.

## Регенерация

Из корня репозитория, Python 3.11 с локальной базой часовых поясов IANA:

```bash
PYTHONPATH=src python -m genesis.generation.datasets export --configs data/configs --output regenerated-data
PYTHONPATH=src python -m genesis.generation.datasets check --dataset regenerated-data
PYTHONPATH=src python -m genesis.generation.datasets check --dataset data
```

```powershell
$env:PYTHONPATH = 'src'
python -m genesis.generation.datasets export --configs data/configs --output regenerated-data
python -m genesis.generation.datasets check --dataset regenerated-data
python -m genesis.generation.datasets check --dataset data
```

В Windows при отсутствии системной базы IANA установите тестовые зависимости из `tests/requirements-schema.lock` заранее. В них зафиксирован пакет `tzdata`. После подготовки команды выполняются без сети. `export` требует новый каталог, чей родитель уже существует. Повторный экспорт выполняйте в другой новый каталог. `check` пересчитывает данные, индексы и сводку и сравнивает точные байты. Дополнительные файлы, каталоги и ссылки считаются ошибкой. `README.md` допускается как документация в корне и не участвует в хэшах.

Тесты проверяют все двадцать книг по актуальным JSON Schema, повторную генерацию в двух независимых каталогах, ссылочную целостность, баланс и наличие публичных доказательств. Для чистого, одиночного и двух взаимодействующих случаев выполняется отдельная сверка записей.
