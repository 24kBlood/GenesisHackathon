# Локальная проверка воспроизводимости

[Индекс](local_eval_profiles.json) содержит 20 открытых синтетических профилей версии 1.0.0. В нём пять чистых эпизодов, пять с взаимодействиями и десять с одиночными и смешанными ошибками всех четырёх типов. Seed и комбинации предназначены для диагностики проекта. Профили отделены от сдаваемых train/dev данных и от закрытой выборки организаторов.

Из корня проекта на Python 3.11 с подготовленной локальной базой IANA:

```bash
PYTHONPATH=src python -m genesis.evaluation.reproducibility verify
PYTHONPATH=src python -m genesis.evaluation.reproducibility benchmark
PYTHONPATH=src python -m unittest discover -s tests -p 'test_reproducibility_and_permutation.py' -v
```

В PowerShell выполните `$env:PYTHONPATH='src'` перед теми же командами `python`. Установка тестовых зависимостей документирована в [контракте данных](../docs/DATA_CONTRACT.md). После подготовки команды проверки выполняются офлайн. Встроенные политики запускаются доверенным локальным драйвером. Проверка изоляции произвольного кода выполняется отдельно.

## Результат проверки

| Условие | Успешно |
| --- | ---: |
| Новый генератор и среда, идентичные исходные параметры и записанная последовательность действий | 20 / 20 |
| Перестановка таблиц и биекция ID, пересчёт доказательств, `Oracle` и `simple_reconciliation` после обратного отображения | 20 / 20 |

SHA-256 рассчитывается в памяти по каноническому JSON. Для повтора сравниваются открытые записи, эталон, provenance, публичный reset, шаги с бюджетом и флагами, и детерминированный итог. Часы для проверки повтора фиксированы. Проверка тайм-аута использует управляемое время. Результат при несовпадении называет открытый профиль, проверяемый компонент и путь первого различия (этот безопасный путь также сохраняется в выводе `genesis.cli verify --all`). Содержимое эталона и его хэш остаются в доверенном коде.

Парная проверка переставляет записи, обновляет их непрозрачные ключи и ссылки, в том числе ссылку возврата на платёж, и сверяет эквивалентность результатов после обратного отображения как для `OraclePolicy`, так и для публичной политики `simple_reconciliation`. Ссылка FX по дате и валютам и ключ `policy` сохраняют значение. Для каждого заявленного набора доказательств проверяется расхождение напрямую по открытым записям. Это верификация синтетических сценариев v1 с указанной политикой. Для новых правил учёта нужно добавить отдельные проверки.

## Измеренные результаты четырёх политик

Один и тот же набор из 20 исходных профилей (`5` чистых, `5` взаимодействующих, `10` одиночных/смешанных) и новая политика на каждый эпизод. Случайный исследователь получает фиксированный seed `89131`. `P`, `R`, `F1`, возврат, шаги и время (`wall_time_seconds`, отдельно) усреднены по 20 эпизодам. Диапазон показывает минимум и максимум возврата.

| Политика | P | R | F1 | Возврат | Шаги | Диапазон возврата | Среднее время, с/эпизод |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Случайная (`random`) | 0,0000 | 0,0000 | 0,2500 | −0,5040 | 9,00 | −1,000…0,984 | 0,0004 |
| Базовая сверка (`simple_reconciliation`) | 0,7500 | 0,7500 | 1,0000 | 0,9920 | 5,00 | 0,992…0,992 | 0,0004 |
| «Пометить всё» (`mark_all`) | 0,0000 | 0,0000 | 0,0000 | −1,0000 | 2,00 | −1,000…−1,000 | 0,0004 |
| Oracle (`oracle`) | 0,7500 | 0,7500 | 1,0000 | 1,0000 | 1,00 | 1,000…1,000 | <0,0001 |

Время измеряется часами `perf_counter` от завершения подготовки эпизода до терминального ответа, выводится отдельно (`wall_time_seconds`) и не участвует в хэше. На пяти чистых эпизодах `oracle` и `simple_reconciliation` посылают пустой ответ, для которого `P = R = 0`, а `F1 = 1`; это объясняет среднее `0,7500` для `P` и `R`. Высокий результат `simple_reconciliation` на компактных 4-обязательных профилях подтверждает публичную проверяемость контракта v1 и не является оценкой реального аудита или ML-обобщения. Официальные баллы определяются жюри на закрытых эпизодах.
