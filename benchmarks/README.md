# Локальная проверка воспроизводимости

[Индекс](local_eval_profiles.json) содержит 20 открытых синтетических профилей версии 1.0.0. В нём пять чистых эпизодов, пять с взаимодействиями и десять с одиночными и смешанными ошибками всех четырёх типов. Seed и комбинации предназначены для диагностики проекта. Профили отделены от сдаваемых train/dev данных и от закрытой выборки организаторов.

Из корня проекта на Python 3.11 с подготовленной локальной базой IANA:

```bash
PYTHONPATH=src python -m genesis.evaluation.reproducibility verify
PYTHONPATH=src python -m genesis.evaluation.reproducibility benchmark
PYTHONPATH=src python -m unittest discover -s tests -p 'test_reproducibility_and_permutation.py' -v
```

В PowerShell выполните `$env:PYTHONPATH='src'` перед теми же командами `python`. Установка тестовых зависимостей документирована в [контракте данных](../docs/DATA_CONTRACT.md). После подготовки команды проверки выполняются офлайн. Встроенные политики запускаются доверенным локальным драйвером. Проверка изоляции произвольного кода выполняется отдельно.

## Результат проверки

| Условие | Успешно |
| --- | ---: |
| Новый генератор и среда, идентичные исходные параметры и записанная последовательность действий | 20 / 20 |
| Перестановка таблиц и биекция ID, пересчёт доказательств, Oracle после обратного отображения | 20 / 20 |

SHA-256 рассчитывается в памяти по каноническому JSON. Для повтора сравниваются открытые записи, эталон, provenance, публичный reset, шаги с бюджетом и флагами, и детерминированный итог. Часы для проверки повтора фиксированы. Проверка тайм-аута использует управляемое время. Результат при несовпадении называет открытый профиль, проверяемый компонент и путь первого различия. Содержимое эталона и его хэш остаются в доверенном коде.

Парная проверка переставляет записи, обновляет их непрозрачные ключи и ссылки, в том числе ссылку возврата на платёж. Ссылка FX по дате и валютам и ключ `policy` сохраняют значение. Для каждого заявленного набора доказательств проверяется расхождение напрямую по открытым записям. Это верификация синтетических сценариев v1 с указанной политикой, включая выбор FX по дате платежа. Для новых правил учёта нужно добавить отдельные проверки.

## Измеренные результаты четырёх политик

Windows, AMD Ryzen 7 7435HS, 8 физических ядер, CPython 3.11.16. Один и тот же набор из 20 исходных профилей и новая политика на каждый эпизод. Случайный исследователь получает фиксированный seed 89131. P, R, F1, возврат, шаги и время усреднены по эпизодам. Диапазон показывает минимум и максимум возврата.

| Политика | P | R | F1 | Возврат | Шаги | Диапазон возврата | Время, мс |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Случайная | 0,0000 | 0,0000 | 0,2500 | −0,5040 | 9 | −1,000…0,984 | 0,625 |
| Простая сверка FX | 0,3500 | 0,1875 | 0,4867 | −0,0315 | 5 | −1,000…0,992 | 1,376 |
| «Пометить всё» | 0,0000 | 0,0000 | 0,0000 | −1,0000 | 2 | −1,000…−1,000 | 0,691 |
| Oracle | 0,7500 | 0,7500 | 1,0000 | 1,0000 | 1 | 1,000…1,000 | 0,091 |

Время измеряется часами `perf_counter` от завершения подготовки эпизода до терминального ответа. Агрегированные времена выводятся отдельно и не участвуют в хэше. На чистых эпизодах Oracle посылает пустой ответ, для которого P и R равны 0, а F1 равно 1. Это объясняет среднее 0,75 для P и R. Цифры получены на открытой локальной диагностике, официальные баллы жюри пока неизвестны.
