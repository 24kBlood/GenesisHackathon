# Граница оценщика и внешней политики

Доверенный координатор вызывает `reset(seed, config)`, выбирает эпизод и хранит терминальный отчёт. Внешняя политика работает в отдельном контейнере. Она читает опубликованные данные через ответы разрешённых инструментов и передаёт действие через stdout. Oracle, эталон, provenance, seed и внутренние ошибки остаются у оценщика. Подробности разделения описаны в [ADR 0002](ADR/0002-evaluator-isolation.md).

## Протокол

Координатор отправляет кадр `{"type":"reset","observation":...,"info":{}}`. Затем работник отправляет один объект действия и ждёт кадр `{"type":"step","observation":...,"reward":0,"terminated":false,"truncated":false,"info":{}}`. У действий нет диалога сброса. Валидное JSON-сообщение с неизвестным действием или неверными аргументами обрабатывает среда. Неизвестный ID получает публичную ошибку.

Каждый кадр заканчивается LF. Предел stdin/stdout равен 512 КиБ, включая LF. Невалидный UTF-8, некорректный JSON, повторный ключ объекта, непредставимое конечным числом значение и превышение лимита прерывают транспорт. Stderr отделён от потока сообщений, ограничен 8 КиБ полезных байтов на строку и 64 КиБ за эпизод, включая разделители в общем размере. Его содержимое отбрасывается. Дедлайн проверяется по монотонным часам для запуска, чтения и записи. Сбой протокола до принятия подачи сохраняет доверенный код причины и усечённый итог с F1 = 0 и наградой −1. Невозможность запустить инфраструктуру прерывает оценку. При обрыве подтверждения после принятой подачи результат вычисляется после завершения изоляции.

В закрытом режиме после `submit` координатор отправляет нейтральный итоговый кадр с наградой 0 и завершает работу контейнера до чтения терминального отчёта. Matcher выполняется после подтверждённого удаления контейнера. Если удаление подтвердить не удалось, координатор возвращает ошибку инфраструктуры и закрытая оценка не выполняется. В открытом режиме среда вычисляет терминальную награду, которую получает политика. В обоих режимах подробная диагностика доступна только стороне оценщика.

## Запуск контейнера

Доверенный оператор заранее готовит локальный Linux-образ с кодом политики и указывает его при создании `DockerPolicy`. Образ выбирается по неизменяемому ID, автоматическая загрузка образа отключена. Образы с объявленными томами отклоняются. Аргументы Docker фиксированы, вызов выполняется без оболочки. Управляющему Docker CLI доступен ограниченный набор переменных запуска, а контейнер получает окружение подготовленного образа без добавления переменных хоста.

Политика работает с UID/GID 65532, без сети и IPC, с корнем только для чтения, без Linux capabilities и с `no-new-privileges`. По умолчанию пределы составляют 32 PID, 512 МиБ памяти вместе со swap и одно ядро CPU. Координатор может поднять ресурсы до 2 CPU и 4 ГиБ и подключить ограниченный `tmpfs` для `/tmp`. Политика получает только свои потоки и временную директорию, если она запрошена. Хостовые каталоги и сокет Docker остаются за пределами контейнера. Docker создаёт обычные системные псевдофайловые системы контейнера. Он не сохраняет stdout/stderr политик в драйвер журналирования. При выходе или дедлайне координатор закрывает канал, останавливает процесс подключения и удаляет именованный контейнер с томами.

## Воспроизводимая проверка

Обычные тесты запускают отдельные процессы с синтетическими публичными действиями. Они сравнивают публичные байты при разных эталонах, проверяют порядок закрытой оценки, ошибки транспорта и итог после молчания и EOF. Эти тесты проверяют протокол и разделение процессов. Системные ограничения проверяет отдельный GitHub Actions job на Linux через фактический запуск контейнера и `docker inspect`.

```sh
docker build --tag genesis-policy-smoke:local tests/fixtures/policy_smoke
GENESIS_POLICY_SMOKE_IMAGE=genesis-policy-smoke:local PYTHONPATH=src \
  python -m unittest discover -s tests -p test_evaluator_isolation.py -v
```

Раннер рассчитан на доверенный локальный Docker Engine с Linux-контейнерами и отдельно проверенный образ. Подготовка образа может требовать доступа к реестру. Сам прогон политики работает без сети. Комплект поставки и единая команда проверки относятся к RUN-18 (#24).
