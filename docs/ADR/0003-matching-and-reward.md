# ADR 0003. Сопоставление и награда

**Статус** — предложено. Основание — ТЗ FinTech §04–05, §06 и §10.

## Валидация

`submit` принимает объект `{episode_id, findings}`. Допускается до 30 выводов. Вывод содержит `type`, `affected_ids`, `claimed_amount_minor`, `currency`, `evidence_ids` и `explanation`. Допускается до 10 ID доказательств и до 1 000 символов объяснения. Объяснение хранится как короткое обоснование. В сопоставлении участвуют структурированные поля.

Неверная структура или нарушение лимита завершает эпизод с итоговой наградой `-1` и ошибкой в журнале оценщика. Синтаксически корректные, но неверные утверждения об ID, сумме, валюте или доказательствах остаются отдельными выводами и могут дать FP. Проверяем строгие типы полей. Идентификаторы сохраняют точное значение и регистр, канонизация списков ID выполняется по задокументированному правилу множества.

## Сопоставление

Кандидатная пара «вывод — эталонная ошибка» появляется при выполнении всех условий.

1. Совпадают тип и каноническое множество затронутых ID.
2. Совпадает валюта, денежная разница в minor units не больше явно заданного допуска для типа. Предлагаемый допуск по умолчанию — 0, поскольку расчёт и правило округления заданы в открытых данных. Любой ненулевой допуск версионируется и публикуется.
3. Все переданные ID доказательств принадлежат открытому каталогу эпизода. Среди них есть хотя бы один полный допустимый набор, заданный оценщиком. Правильный неключевой ID из каталога сам по себе совпадения не создаёт.

Ключ группы дублей — `(type, canonical_affected_ids, claimed_amount_minor, currency)`. Разные `evidence_ids` и `explanation` в одной группе допускают максимум один TP. Группа имеет ребро к эталонной ошибке, если хотя бы один её исходный вывод удовлетворяет всем условиям. Каждый набор доказательств проверяем отдельно, без объединения между выводами.

На двудольном графе групп и эталонных ошибок находим паросочетание максимальной мощности. Порядок обхода задаём сортировкой ключей групп и `issue_id`. Для сопоставленной группы из выводов, удовлетворяющих условиям выбранной пары, берём первый по отсортированному набору `evidence_ids`, а при равенстве выбираем меньший индекс во входном списке. Он считается TP. Каждый другой вывод группы считается FP. Проверка генератора отклоняет эталонные ошибки с одинаковым типом, затронутыми ID, суммой и валютой.

Сопоставленная пара даёт TP. Каждый несопоставленный исходный вывод даёт FP, включая повторы. Каждый несопоставленный эталон даёт FN. Публикуем версии нормализации, допусков и разрешения неоднозначности вместе с кодом оценщика.

## Метрики и возврат

```text
P  = TP / (TP + FP)
R  = TP / (TP + FN)
F1 = 2 * TP / (2 * TP + FP + FN)
reward = clip(2 * F1 - 1 - 0.002 * inspection_steps, -1, 1)
```

При нулевом знаменателе P или R равны нулю. При пустом эталоне и пустом ответе F1 равен единице. При пустом эталоне и наличии выводов F1 равен нулю. Усечение оценивается по пустому итоговому ответу и фактическим исследовательским шагам. Итоговая награда за неверную структуру берётся из правила `-1`. Возврат равен итоговой награде. Статус и правила публикации награды следуют [ADR 0002](0002-evaluator-isolation.md).

Пример с одним TP и без FP или FN после десяти исследовательских шагов даёт F1 = 1 и возврат 0,98. Повтор того же вывода добавляет FP, уменьшая F1 до 2/3 и возврат примерно до 0,3133 при том же числе шагов.

## Какие проверки добавим

- Сопоставление при конкурирующих рёбрах. Один эталон учитывается один раз. Порядок не меняет число TP, FP и FN.
- Чистый эпизод, пустой ответ при ошибках, дубли с изменённым объяснением, неполное доказательство, неверный ID или валюта, допуск на границе и превышение лимитов.
- Полный верный ответ выигрывает у молчания на ошибочных данных. На чистых данных молчание выигрывает у ложных выводов. Проверяем низкую награду стратегии «пометить всё» и разницу 0,002 для одного лишнего шага при равном результате без отсечения.
