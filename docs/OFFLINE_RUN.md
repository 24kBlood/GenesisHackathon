# Автономная проверка Genesis

## Один вызов

Локально используйте Python 3.11 и зафиксированные тестовые зависимости. Установка может обращаться к реестру. После установки проверка выполняется по локальным файлам.

```sh
python -m pip install --no-deps -r tests/requirements-schema.lock
PYTHONPATH=src python -m genesis.cli verify --all
```

В PowerShell задайте `$env:PYTHONPATH = 'src'` и запустите `python -m genesis.cli verify --all`. Команда выводит статус, количество и длительность по группам, а при сбое сообщает имя первой проверки и класс ошибки. Полный текст исключений, пути и закрытые входы из тестов в журнал команды не попадают.

Проверяются схемы, наборы train/dev, матрицы C01–C20 и E01–E20, траектории, переходы и награда, 20 повторов и 20 пар с перестановкой ID. Отдельно выводятся средние P, R, F1, возврат, шаги и время четырёх политик на 20 открытых диагностических профилях. Это результаты команды на синтетических данных. Закрытый прогон проводит жюри. [Матрица QA](QA_CHECKLIST.md).

## Сборка и перенос

Dockerfile фиксирует официальный базовый образ Python 3.11 по digest. При сборке сначала скачиваются зафиксированные wheel-файлы. Установка в слое зависимостей использует только эти файлы. Финальный образ содержит установленный набор, исходники и локальные тестовые артефакты. Сборка может требовать доступа к Docker Hub и PyPI. Для переноса уже собранного образа можно использовать `docker save` и `docker load` без скачивания при запуске.

```sh
docker build --tag genesis-verify:local .
docker run --rm --pull never --network none --cpus 2 --memory 4g --memory-swap 4g \
  --read-only --tmpfs /tmp:rw,nosuid,nodev,noexec,size=64m,mode=1777 \
  --cap-drop ALL --security-opt no-new-privileges --pids-limit 64 \
  genesis-verify:local python -m genesis.cli verify --all
```

Образ запускается как UID/GID 65532. Исходники и входы доступны для чтения. Тесты записывают временные данные в ограниченный `/tmp`. В CI проверяются параметры фактического контейнера и поле `.Size` образа Docker Engine в байтах с пределом 1 000 000 000. Длительности измеряются на машине запуска. Контрольный прогон подставляет нарушенный JSON диагностического профиля и проверяет код 1.

## Системная изоляция политики

Контейнер полной проверки имеет предел 2 CPU и 4 ГБ RAM. Контейнеры внешних политик проверяет отдельный workflow `Policy isolation` на доверенном хосте. Координатор запускает работника с отдельными ресурсами и обменивается JSONL. Дедлайн по умолчанию составляет 60 секунд, бюджет — 100 действий. Раннер не предоставляет политике сокет Docker, монтирования, секретные переменные или сеть. [Описание изоляции](ISOLATION_AND_LEAKAGE.md).

Внутри образа проверки `docker-policy-smoke` помечается `SKIP`. Если на доверенном хосте заранее собран smoke-образ и задана переменная `GENESIS_POLICY_SMOKE_IMAGE`, используйте `python -m genesis.cli verify --all --require-docker`, чтобы эти проверки стали обязательными в том же запуске. [Offline verification workflow](../.github/workflows/offline-verify.yml).
