# Публичные траектории v1

[Траектория](../trajectories/trajectories.jsonl) записана реальным запуском `simple_reconciliation` на открытом синтетическом FX-эпизоде `ep-cf50625d`. В файле один эпизод и пять принятых шагов. Четыре исследовательских действия дают нулевую награду, пятый шаг принимает вывод и возвращает в открытом режиме 0,992.

SHA-256 файла — `978246df1473500ad3e1208cc434767611dbfb152af568bb2ad9b40794526c4d`.

## Регенерация и replay

Из корня репозитория на Python 3.11 с установленными зависимостями из [тестового lock-файла](../tests/requirements-schema.lock):

```sh
PYTHONPATH=src python tests/test_trajectories.py --export
PYTHONPATH=src python -m unittest discover -s tests -p test_trajectories.py -v
```

В PowerShell задайте `$env:PYTHONPATH = 'src'` перед запуском. Команда экспорта перезапишет указанный выше файл из публичного FX-примера и проверит строки локальным реестром схем. Тест replay берёт действия из файла, передаёт их в среду и сравнивает получившиеся байты. Кодировка UTF-8, ключи отсортированы, разделитель и окончание строк LF.

## Граница публичных данных

Доверенный координатор подключает `TrajectoryRecorder(mode=...)` через `await run_episode(..., on_step=recorder.record)`. Каждый новый прогон получает свой recorder. Метод `to_jsonl()` сериализует разрешённые поля. Для проверки можно передать `validate_shape` в `validate_trajectory` из локального реестра [схемы траектории](../schemas/trajectories.schema.json). Внешний экспорт создаётся только для обычной политики на проверенных синтетических данных. Эталон, источник данных, диагностика, `info`, stderr и измеренное время остаются вне файла. Oracle в публичном наборе отсутствует.

В закрытом режиме награда в каждой строке равна нулю, включая завершающий `submit`. Текст пояснения выводов заменяется пустой строкой. Структурированные доказательства и суммы сохраняются, поэтому эта замена не влияет на сопоставление. Неудачное действие записывается как `{"type":"invalid"}`, а в наблюдении остаётся публичный код ошибки, если среда его выдала. При невалидном `submit` сохраняются флаг завершения и нейтральный статус `submitted`; причина остаётся в доверенном отчёте. Маркер не восстанавливает исходный невалидный ввод и его точный результат при replay. Для таких проверок используют заранее известную доверенную последовательность тестовых действий.

`reset` и timeout до принятия очередного действия не добавляют строку. Бюджетное усечение следует за сотым принятым действием и записывается на нём. При timeout или обрыве транспорта файл может закончиться префиксом без терминальной строки. Причина усечения и фактическое число принятых действий остаются в отдельной доверенной диагностике.
